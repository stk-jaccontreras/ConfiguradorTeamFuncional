# Casos de Uso

## Casos de Uso

### Identificación de Caso de Uso

| ID de Caso de Uso | Para cada caso de uso es necesario brindarle un identificador entero único.  Casos de uso relacionados pueden ser agrupados según su jerarquía. |
| --- | --- |
| Nombre del Caso de Uso | Nombre conciso y orientado a la funcionalidad que refleje la tarea que el usuario necesita efectuar utilizando el sistema. Incluir un verbo y un sustantivo.   <br>Ejemplo:<br>Actualizar Usuarios |
| Creado por | Nombre de la persona que inicialmente documento el caso de uso. Este campo debe ser cambiado en las subsecuentes actualizaciones de este Caso de Uso por el dato contenido en la casilla de “Última Actualización por” |
| Fecha Creación | Fecha en la cual el caso de uso fue inicialmente documentado |
| Última Actualización por | Nombre de la persona que efectúo la última actualización del caso de uso. Debe ir cambiando conforme se actualice el Caso de Uso |
| Fecha última actualización | Fecha en la que se efectúo la última actualización del caso de uso. |

### Definición de Caso de Uso

| Actores: |
| --- |
| Un actor es una persona u otra entidad externa al sistema que interactúa con el mismo y ejecuta casos de uso para efectuar una tarea. |
| Descripción: |
| Breve descripción de la razón, o descripción de alto nivel de la secuencia de acciones y resultado de la ejecución del caso de uso. |
| Precondiciones: |
| Listar las actividades que se deben llevar a cabo o cualquier condición que tiene que ser cumplida antes de ejecutar el caso de uso. Numerar cada entrada. |
| Post-Condiciones: |
| Describe el estado del sistema después de la ejecución del caso de uso. Es necesario numerar cada salida. |
| Flujo Normal: |
| Proveer una descripción detallada de las acciones del usuario y de las respuestas del sistema que se van a llevar a cabo durante la ejecución del caso de uso bajo las condiciones normales y esperadas. |
| Flujo Alternativo: |
| Proveer una descripción detallada de otros escenarios que se puedan dar dentro del caso de uso. |
| Variantes: |
| Condiciones que se deben de validar y que pueden ocurrir durante la ejecución del caso de uso y cuyo comportamiento del sistema puede ocasionar un error. |
| Prioridad: |
| Indicar la prioridad relativa de implementar la funcionalidad requerida. |
| Frecuencia de uso: |
| Estimar el número de ocasiones que el caso de uso será ejecutado por los actores en alguna unidad de tiempo apropiada. |
| Reglas de Negocio: |
| Listar las reglas del negocio que tengan influencia sobre el caso de uso. |
| Requerimientos Especiales: |
| Identificar cualquier requerimiento especial, requerimientos no funcionales, que se deban tener en cuenta durante el diseño o implementación. |
| Premisas: |
| Listar cualquier suposición que fue hecha durante el análisis. |
| Notas: |
| Notas. |
